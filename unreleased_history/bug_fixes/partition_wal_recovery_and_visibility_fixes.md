Fixed recovery and visibility gaps with `wal_partitions > 1` (EXPERIMENTAL). A point-in-time recovery that cuts the WAL set below a void now supersedes every record and void above the cut, and makes that declaration durable before `DB::Open()` returns, so every later open in any recovery mode succeeds; previously the next reopen could fail with "bears records and a void cover" or "holds a void over wal_index". A WAL index supersession record now also supersedes voids, with no change to its layout: a binary without this fix that reads such a WAL set fails closed with "bears records and a void cover", as before. Point-in-time recovery also stops at a record that fails to apply even when another partition's report is pending. A write that returned an error is no longer visible: `LockWAL()`, `SetDBOptions()` and `CreateColumnFamilyWithImport()` wait for sync groups that have not yet published, tailing iterators show only published writes, and WritePrepared and WriteUnprepared transactions run their commit callbacks only once no lower write can fail them. An open with `track_and_verify_wals` now merges a WAL set written with more than one partition instead of replaying it file by file. The merge also checks predecessor spans and sequence numbers more strictly, and its errors name the WALs involved. RepairDB, `GetUpdatesSince()` and `ldb dump_wal` refuse a WAL of an indexed DB whose head cannot be read. `DB::Resume()` now zeroes a large failed record that reached its WAL only in part from the end of the last whole record.
