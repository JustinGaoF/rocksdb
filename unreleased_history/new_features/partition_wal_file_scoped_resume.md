With `wal_partitions > 1`, `DB::Resume()` and automatic error recovery now resume a DB stopped by a file-scoped WAL write error (`IOStatus::IOErrorScope::kIOErrorScopeFile`) on any partition, instead of returning `Status::NotSupported` until the DB is reopened. Recovery replaces every partition's WAL, atomically flushes every live column family and retires every WAL at or below the failed one, in memory and in the MANIFEST WAL set. It never reads, rewrites or syncs the failed file again. The failed write, and every write that failed behind it, stay invisible before and after the resume and after any later reopen, and their sequence numbers are never reused. The configurations that file-scoped recovery already refused (`manual_wal_flush`, `allow_2pc`, `WAL_ttl_seconds`, `WAL_size_limit_MB`, blob direct write) still refuse it, and so does `track_and_verify_wals_in_manifest` with one WAL partition.
